对应考核内容:**Python 基础 · 环境与包管理(Conda / uv / venv,独立环境、依赖安装与环境记录)**

## 1. 为什么一定要用独立环境

假设两个项目:项目 A 需要 `numpy 1.26`,项目 B 需要 `numpy 2.5`。
如果所有包都装进系统的那个 Python,两个项目就会互相打架——这就是"依赖冲突"。

解决办法是给每个项目一个**独立的解释器 + 独立的包目录**,叫虚拟环境。
项目文件夹删掉,环境跟着删掉,互不污染。

⚠️ 本项目的情况:系统里那个 Python 是 3.14,而 PyTorch 当时还没有 3.14 的轮子。
如果直接用系统 Python,连装都装不上。所以我们专门拉了一个 Python 3.12 的环境。

## 2. 三个工具的关系

| 工具 | 定位 | 特点 |
| --- | --- | --- |
| `venv` | Python 自带 | 只创建虚拟环境,不管下载和版本锁定 |
| `conda` | 科学计算全家桶 | 能装 Python 本身和非 Python 库(CUDA 等),体积大、解析依赖慢 |
| `uv` | 新一代包管理器(Rust 写的) | 装环境、装包、锁版本一体,速度比 pip 快一个数量级 |

结论:日常开发用 `uv` 足够,它内部同样使用 Python 官方的 venv 机制;
需要装 CUDA Toolkit 这类系统级依赖时才轮到 conda。

## 3. 我们项目的四个关键文件

```
.python-version    → 声明本项目用 Python 3.12
pyproject.toml     → 声明项目需要哪些依赖(人写的)
uv.lock            → 记录每个依赖的精确版本和哈希(机器写的,不要手改)
.venv/             → 真正的虚拟环境目录(不入库)
```

`pyproject.toml` 和 `uv.lock` 是"环境记录"的核心:
换一台电脑,`uv sync` 就能还原出**一模一样**的环境。

### pyproject.toml 逐段解读

```toml
[project]
name = "ai-image-classification"
requires-python = ">=3.12"
dependencies = [
    "numpy>=2.5.4",        # 只约束下界,允许装更新的
    "torch>=2.9.0",
    ...
]
```

```toml
[[tool.uv.index]]
name = "pytorch-cu128"
url = "https://download.pytorch.org/whl/cu128"
explicit = true

[tool.uv.sources]
torch = [{ index = "pytorch-cu128" }]
torchvision = [{ index = "pytorch-cu128" }]
```

这段是整个环境里最"值钱"的部分。PyPI 上的 torch 默认是 CPU 版本;
RTX 5060 是 Blackwell 架构(算力 sm_120),必须用 CUDA 12.8 及以上编译的版本。
所以这里单独指定了一个官方源,并且只在装 torch / torchvision 时使用它
(`explicit = true`),其他包仍然走 PyPI。

```toml
[tool.uv]
link-mode = "copy"
```

uv 默认用硬链接节省磁盘,但我们的缓存盘(C:)和项目盘(D:)不是同一个卷,
硬链接会失败并告警,所以显式改成复制。

## 4. 常用命令

| 命令 | 作用 |
| --- | --- |
| `uv sync` | 按 uv.lock 还原环境(换机器后的第一条命令) |
| `uv add 包名` | 新增依赖,自动写进 pyproject.toml 并更新锁文件 |
| `uv remove 包名` | 移除依赖 |
| `uv run 脚本.py` | 在项目环境里运行脚本,不用手动激活环境 |
| `uv pip list` | 查看当前环境装了哪些包 |
| `uv lock --upgrade` | 在允许范围内升级依赖版本 |

注意 `uv run` 的便利:它会自动检查环境是否和锁文件一致,不一致就先同步。
所以不需要像以前那样 `activate` 再 `pip install`。

## 5. 动手练习

在 `D:\workspace\ai-image-classification` 目录下打开终端,依次执行:

```powershell
# 1. 看看当前环境装了哪些包(对比 pyproject.toml 里声明的)
uv pip list

# 2. 运行自检脚本,确认 CUDA 可用
uv run scripts/check_env.py

# 3. 新增一个包,观察 pyproject.toml 和 uv.lock 被自动修改
uv add rich

# 4. 再删掉它,观察文件被改回去
uv remove rich

# 5. 查看 git 状态,确认这两个文件被改过
git status
```

第 3、4 步很重要:亲手看到"改依赖 → 锁文件跟着变"这个联动,
就理解了为什么它能保证环境可复现。

---

## 参考答案要点

1. 体积大(本项目 4.4 GB)、含平台相关的二进制文件,无法跨机器复用,应由锁文件还原。
2. 前者是"允许的范围",后者是"实际锁定到的版本",前者给人看意图,后者保证可复现。
3. 会从 PyPI 装到 CPU 版本的 torch,代码能跑但 `cuda.is_available()` 为 False。
4. `git clone` 后执行 `uv sync`,再按 README 跑 `uv run scripts/check_env.py` 验证。
5. PyTorch 的轮子发布通常滞后于最新 Python 版本,3.14 当时没有可用轮子;
   3.12 是当前第三方生态兼容性最好的版本。
